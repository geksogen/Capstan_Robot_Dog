# Интеграция прошивки робособаки (ESP32) с ROS 2 и Gazebo

В данной директории подготовлен ROS 2 пакет `capstan_leg_sim`, который полностью переносит логику управления ногой (инверсная кинематика, генерация походки, стабилизация по IMU) из прошивки ESP32 (`Leg_step_abduction_Roll_Pitch.ino`) в симуляцию Gazebo через механизм `ros2_control`.

## Анализ архитектуры прошивки

Оригинальная прошивка написана на C++ (PlatformIO) и выполняет роль контроллера верхнего уровня для одной ноги:
1. **Приводы:** 3 бесколлекторных мотора (BLDC) с драйверами ODrive. Два мотора (A и B) образуют пятизвенный механизм шага, третий мотор (ABAD) отвечает за отведение ноги (крен). Редукция 10:1. Прошивка общается с ними по шине CAN (отправка `target_turns`).
2. **Датчики:** IMU BNO086 (I2C) на 100Гц, из которого извлекаются углы крена (Roll) и тангажа (Pitch) для 3D-стабилизации.
3. **Цикл управления:** Жестко задан на 5 мс (200 Гц). В цикле генерируется кривая Безье для фазы переноса стопы, вычисляется инверсная кинематика (IK) и накладываются компенсационные смещения (Pitch сдвигает X стопы, Roll меняет угол ABAD). Имеются аппаратные лимиты (Pitch ограничен до ±0.174 рад, Roll до ±0.523 рад).
4. **Интерфейс:** Управление параметрами походки (высота, длина шага, клиренс) реализовано через символьные команды (`w`, `s`, `d`, `a`, и т.д.) по Serial порту.

## Что перенесено в ROS 2

Для симуляции был выбран подход "Standalone Node + Forward Controller". Это архитектурно 1-в-1 повторяет железо:
* **ESP32** заменена на ROS 2 C++ ноду (`leg_controller_node`). Нода содержит *идентичный* математический код кинематики, генератора Безье и стабилизации.
* **Шина CAN и ODrive** заменены на `gazebo_ros2_control` и плагин `position_controllers/JointGroupPositionController`. Вместо отправки `turns` по CAN, нода публикует целевые углы в радианах в топик контроллера.
* **BNO086** заменен на Gazebo IMU Sensor Plugin. Нода подписывается на топик `/imu/data`.
* **Serial порт (клавиатура)** заменен на топик `/serial_cmd` (`std_msgs/String`).

## Структура пакета
* `urdf/leg.urdf.xacro` — описание физической модели ноги с плагинами Gazebo и ros2_control.
* `config/controllers.yaml` — настройка аппаратного интерфейса для управления по позиции.
* `src/leg_controller_node.cpp` — точная копия математики из ESP32, обернутая в ROS 2 Node.
* `launch/sim.launch.py` — запуск Gazebo, спавн модели, загрузка контроллеров и запуск узла кинематики.

## Как запустить и проверить (ROS 2 Humble / Gazebo Classic)

1. **Сборка:**
   Скопируйте директорию `src/capstan_leg_sim` в ваш ROS 2 workspace (например, `~/ros2_ws/src/`).
   ```bash
   cd ~/ros2_ws
   colcon build --packages-select capstan_leg_sim
   source install/setup.bash
   ```

2. **Запуск симуляции:**
   ```bash
   ros2 launch capstan_leg_sim sim.launch.py
   ```
   *Запустится Gazebo. Модель ноги появится в пространстве, загрузятся контроллеры, и нода начнет цикл шага.*

3. **Отправка тестовых команд (аналог джойстика):**
   Откройте новый терминал и публикуйте символы в топик (имитация нажатия клавиш на ESP32):
   ```bash
   # Увеличить длину шага (кнопка 'd')
   ros2 topic pub --once /serial_cmd std_msgs/msg/String "{data: 'd'}"
   
   # Уменьшить высоту Z (кнопка 's')
   ros2 topic pub --once /serial_cmd std_msgs/msg/String "{data: 's'}"
   ```

4. **Проверка стабилизации:**
   В Gazebo можно выбрать инструмент "Rotate" (Вращение) или приложить силу к базовому звену (`base_link`), чтобы наклонить его по осям X или Y. 
   Так как нода читает `/imu/data` из Gazebo, вы сразу увидите, как нога компенсирует наклон (плечи смещают стопу при тангаже, а шарнир ABAD отклоняется при крене).

## Важные расхождения с железом

При переходе от железа к симуляции существуют фундаментальные отличия, о которых нужно помнить:

1. **Единицы измерения приводов:** В прошивке ESP32 на ODrive отправлялись обороты вала мотора до редуктора (Turns = Angle / 2PI * GEAR_RATIO). В Gazebo контроллер `JointGroupPositionController` управляет непосредственно выходным звеном после редуктора, поэтому нода отправляет чистые **радианы**. Учет `GEAR_RATIO` в симуляции выполняется на уровне URDF (элемент `<mechanicalReduction>`), а не в коде.
2. **Кинематика замкнутой цепи:** Оригинальная нога — это замкнутый пятизвенник. URDF "из коробки" поддерживает только деревья (открытые цепи). Для точной физической симуляции замкнутого контура в Gazebo необходимо использовать `sdf` теги (например, `<sensor>` и `<plugin>` для замыкания колена и стопы). В текущем URDF для валидации алгоритма активированы три приводных сустава; пассивные тяги симулируются как независимые ветви.
3. **Идеализация датчиков:** IMU в Gazebo выдает математически точный кватернион. Реальный BNO086 имеет дрейф, шумы и задержки фильтрации SHTP-протокола. В Gazebo можно добавить гауссов шум (параметры `<noise>` в плагине), чтобы приблизить симуляцию к реальности.
4. **Трение и люфты:** Кабастановые редукторы имеют нулевой люфт, что идеально подходит под симуляцию, но в реальном мире есть вязкое трение и инерция тросов. Динамические свойства в URDF (`<dynamics damping="..." friction="..."/>`) выставлены усредненно и требуют подстройки (System Identification) по логам реального ODrive (токи против скоростей).
